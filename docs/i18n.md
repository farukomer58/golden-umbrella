# Internationalization

## Supported locales

- `tr` — Turkish, primary and default language.
- `nl` — Dutch.
- `en` — English.

## Routing and static export

- Use locale-prefixed URLs such as `/tr/about`, `/nl/about`, and `/en/about`.
- Statically generate every supported locale and every known localized route using `generateStaticParams()` where required.
- The URL locale is authoritative; do not keep a competing locale in Zustand.
- Do not depend on Proxy, middleware, or request-time locale negotiation in a static export.
- Define an explicit root `/` strategy: a Turkish landing page, static-host redirect, or client navigation. A client redirect is not equivalent to an HTTP redirect for SEO.
- Switching languages should preserve the equivalent page; use a defined fallback when the destination translation does not exist.
- Use localized slugs only if a maintained route mapping exists. Otherwise keep stable route segments and translate page content.

## Dictionaries and content

- Keep separate `tr`, `nl`, and `en` dictionaries with identical key structures.
- Use Turkish as the source-of-truth key set, with typed helpers and a completeness check in CI.
- Translate visible text, navigation, labels, validation messages, alt text when language-dependent, metadata, and empty/error states.
- Fail validation on missing keys; do not render raw keys or silently fall back to another language.
- Keep long-form translated content in dedicated files if dictionaries become unwieldy.
- Format dates, numbers, and currencies with `Intl` and the active locale.

## HTML and SEO

- Set the correct `<html lang>` for each generated locale page.
- Generate locale-specific titles, descriptions, canonical URLs, and reciprocal `hreflang` alternates.
- Include the appropriate locale URLs in the sitemap and verify the output on the chosen static host.
- Ensure language navigation is keyboard accessible and clearly announces the selected language.

## Verification

- Confirm the static build generates all required locale paths.
- Test language switching from nested routes and missing-page fallbacks.
- Verify dictionary key parity, localized metadata, `lang` attributes, and direct navigation to exported pages.
